# Eat the World Solo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A standalone, offline-capable country-passport app for one person on one Android phone, with no backend and no running cost.

**Architecture:** A separate Vite + React + Tailwind 4 app in `solo/` that imports the existing pure logic and presentational components from `src/` through the `@` alias, with three small shims standing in for `next/link`, `next/navigation` and `next/dynamic`. Data lives in IndexedDB; stamps are derived from visits and backfills, never stored. A service worker makes it work offline; a JSON export and import is the backup.

**Tech Stack:** Vite, React 19, TypeScript, Tailwind 4 (`@tailwindcss/vite`), `idb`, `vite-plugin-pwa`, Leaflet (existing), Vitest + `fake-indexeddb`, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-21-solo-mode-design.md`

## Global Constraints

- Installs from Android Chrome ("Add to Home screen") and opens offline once loaded; only map tiles need a connection.
- Free hosting, static files only: no database, functions, cron, auth, SMTP or keepalive. Hosting is GitHub Pages on the (soon public) repo, deployed by a GitHub Actions workflow from `main`, served under the subpath `/eat-the-world/` (so `base: "./"`, relative manifest `start_url` and `scope`); Pages cannot set headers, so the page has `<meta name="robots" content="noindex, nofollow">`.
- Data stays on the device. Export and import round-trip every field. The app asks the browser for persistent storage.
- No analytics. No third-party calls except OpenStreetMap tiles. No geocoding service is called at runtime.
- Shared logic is imported from `src/`, never copied. Solo-only code lives in `solo/`. `src/` is not modified (if a change there is unavoidable, stop and say so).
- Vite app in `solo/`; hash routing (`#/country/FR`); IndexedDB through `idb`; one `package.json` and one lockfile; fonts self-hosted (`@fontsource`).
- Seed: 249 countries, 68 London restaurants in 39 countries, and the approved dishes in `seed/signature-dishes.csv`. Coordinates come from postcodes.io at generation time only, and the generated JSON is committed.
- Service worker via `vite-plugin-pwa`; it never caches OSM tiles. This exception to the brief's "no service worker in v1" applies to solo only.
- Headline "N / 249 countries", with "N / 39 London suggestions" underneath. No points, sets, daily cap, groups or accounts.
- Design for 390×844 and one thumb. Use the tokens in `docs/design.md`; never hard-code hex values.
- The group app keeps working: its tests and CI jobs pass unchanged. The Next.js here has breaking changes; solo adds no Next code, but read `node_modules/next/dist/docs/` before touching any.
- Commit as `andrewjpage@gmail.com` on branch `worktree-solo-mode`. End every commit message with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Never push to `main`. Run `npm run lint`, `npm run typecheck` and `npx vitest run tests/solo` before each commit.

## Review Focus

Likeliest first. Each line has its test in the task named.

1. **Browser storage fails** (private window, blocked IndexedDB, quota error on a photo): the app opens with a clear message instead of a blank page, and a photo write failure saves the visit without the photo. Never lose a visit silently. (Tasks 3, 7, 10)
2. **Bad or repeated imports:** the same backup imported twice adds nothing the second time; a file from a newer `schemaVersion`, plain text, or a visit with `rating: 9` is rejected with the existing data untouched; a photo-less backup does not delete photos already on the phone. (Tasks 3, 8)
3. **Dates and edits:** a backdated visit moves the stamp date earlier; a future date is refused; deleting or re-countrying a visit moves or removes the stamp. (Tasks 2, 7)
4. **Location denied, slow or absent:** check-in still saves; a restaurant without coordinates stays off the map; a map with no pins shows an empty state. (Tasks 6, 7, 10)
5. **Two windows open** (installed app plus a Chrome tab): a visit logged in one shows in the other when it regains focus, with no clobbering. (Tasks 5, 10)
